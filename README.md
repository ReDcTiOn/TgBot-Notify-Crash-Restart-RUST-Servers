# RustWatch: уведомления о падениях и рестартах Rust-серверов

Бот следит за несколькими Rust-серверами и пишет в Telegram, когда сервер упал, перезагружается, выключен или снова онлайн. В сообщении есть время события и длительность простоя.

Только уведомления, кнопок и управления серверами нет.

## Как это работает

Два источника данных на каждый сервер:

- **Query (A2S, UDP `game_port + 1`).** Опрос раз в 10 секунд, основной датчик «жив или нет».
- **WebRCON (`game_port + 2`).** Постоянное соединение. Раз в 15 секунд бот запрашивает `serverinfo` (uptime, игроки, флаг `Restarting`) и читает консоль, чтобы отличить штатную остановку от падения.

Сервер считается упавшим, если 3 проверки подряд (~30 с) не отвечают ни Query, ни RCON. Единичный потерянный UDP-пакет тревоги не вызывает.

| Что увидел бот | Сообщение |
|---|---|
| Сервер пропал, перед этим были признаки остановки | ⏹ Остановлен (штатно), с указанием признака |
| Сервер пропал без таких признаков | 💥 КРАШ |
| Вернулся после штатной остановки быстрее 15 мин | 🔄 Рестарт завершён + простой |
| Не вернулся за 15 мин после штатной остановки | 🔴 Выключен (не рестарт) |
| Вернулся после долгой штатной остановки | 🟢 Сервер включён |
| Вернулся после краша | ✅ Поднялся после краша + простой |
| Uptime стал меньше ожидаемого, хотя падения не видели | 🔄 Был рестарт между проверками |

Штатной остановкой считается любой из признаков:

1. строка консоли (не чат) совпала с `shutdown_patterns` из конфига;
2. `serverinfo` вернул `Restarting: true`;
3. сервер закрыл RCON-соединение штатно (WebSocket close frame). При падении процесса соединение обрывается без него.

Состояние хранится в `state.json`. Если бот перезапустить во время простоя сервера, повторного уведомления не будет, а о возвращении сервера он сообщит. Рестарт, случившийся пока бот был выключен, находится по uptime.

## Установка

Бот работает на отдельном VPS, не на машине с игровыми серверами. Иначе при падении машины он замолчит вместе с ними.

```bash
git clone https://github.com/ReDcTiOn/TgBot-Notify-Crash-Restart-RUST-Servers /opt/rustwatch
cd /opt/rustwatch
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp config.example.toml config.toml
cp .env.example .env
```

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен запишите в `.env` (`TELEGRAM_BOT_TOKEN`).
2. Создайте **группу** и включите в ней «Темы» (Topics). У каналов тем нет.
3. Добавьте бота в группу администратором и создайте темы, например по одной на сервер.
4. Узнайте `chat_id` и `thread_id`. Напишите любое сообщение в нужной теме и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. В ответе будут `chat.id` (вида `-100…`) и `message_thread_id`.
5. Впишите их в `config.toml`: `chat_id` и `thread_id` у каждого `[[servers]]`.

### Пароли RCON

Впишите пароли в `.env` (`RCON_PASSWORD_1` … `RCON_PASSWORD_5`). Без пароля сервер работает только по Query: падение будет видно, а причина (краш или штатная остановка) нет.

### Проверка

Перед запуском проверьте, что Query и RCON отвечают, и посмотрите, как выглядят ответы ваших серверов:

```bash
.venv/bin/python -m rustwatch probe
```

Команда выводит ответ Query и сырой ответ `serverinfo` каждого сервера. Проверьте два момента:

- в `serverinfo` есть числовое поле `Uptime` (секунды) и поле `Restarting`;
- какие строки сервер пишет в консоль при остановке: выполните `restart 60` на тестовом сервере и посмотрите лог. Если формулировка отличается, поправьте `shutdown_patterns` в `config.toml`.

Увидеть, как выглядят все уведомления в вашей группе (по одному примеру каждого, в тему первого сервера):

```bash
.venv/bin/python -m rustwatch preview
```

Пробный запуск без отправки в Telegram:

```bash
.venv/bin/python -m rustwatch run --dry-run -v
```

### Запуск как сервис

```bash
sudo useradd -r -s /usr/sbin/nologin rustwatch
sudo chown -R rustwatch /opt/rustwatch
sudo cp deploy/rustwatch.service /etc/systemd/system/
sudo systemctl enable --now rustwatch
journalctl -u rustwatch -f
```

## Ограничения

- Время падения точное до интервала опроса (~10 с).
- Если все пять серверов стоят на одной машине и она упала целиком, придёт пять отдельных сообщений «КРАШ».
- API RustApp не используется: он не отдаёт событий о падениях и рестартах, только поле `status` в `GET /public/servers`.
